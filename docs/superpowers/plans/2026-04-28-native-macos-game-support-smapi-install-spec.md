# SMAPI macOS Installer — Precise Mutation Spec

**Source revision:** `develop` branch, SMAPI 4.5.2 (released 2026-03-22)
**Authoritative files consulted:**
- `src/SMAPI.Installer/assets/install on macOS.command` (sha `e85230e`)
- `src/SMAPI.Installer/InteractiveInstaller.cs` (sha `ed2b614`)
- `src/SMAPI.Installer/Framework/InstallerPaths.cs` (sha `98a21d8`)
- `build/scripts/prepare-install-package.ps1` (sha `74222b5`)

All paths below are relative to `<game>/Contents/MacOS/` (the "game dir" / `installDir`) unless stated otherwise. Steam installs to `~/Library/Application Support/Steam/steamapps/common/Stardew Valley/Contents/MacOS`; GOG installs to `/Applications/Stardew Valley.app/Contents/MacOS`. The installer works identically for both.

## Section 1: Installation Steps (in order)

### Step 0 — Shell bootstrap (macOS.command)

```bash
#!/usr/bin/env bash
cd "`dirname "$0"`"
xattr -r -d com.apple.quarantine internal
internal/macOS/SMAPI.Installer
```

`install on macOS.command` (115 bytes) does exactly three things:
1. `cd` to the installer directory (so relative paths resolve correctly).
2. Recursively strip the `com.apple.quarantine` xattr from everything under `internal/` (the pre-built .NET self-contained installer binary tree).
3. Exec `internal/macOS/SMAPI.Installer` — the self-contained .NET 6 binary that runs `InteractiveInstaller.cs`.

Quarantine removal is scoped to the *installer* tree only. The game bundle itself is not touched by this step.

### Step 1 — Back up `config.user.json` if present

```csharp
if (File.Exists(paths.ApiUserConfigPath))
    File.Copy(paths.ApiUserConfigPath, paths.BundleApiUserConfigPath);
```

- **From:** `<gameDir>/smapi-internal/config.user.json`
- **To:** `<bundleDir>/smapi-internal/config.user.json` (inside the installer package; temporary)
- **Why:** Preserves user's SMAPI console color-scheme preference across reinstalls.

### Step 2 — Restore original launcher if backup exists (always runs)

```csharp
if (context.IsUnix && File.Exists(paths.BackupLaunchScriptPath))
{
    this.InteractivelyDelete(paths.VanillaLaunchScriptPath, allowUserInput);
    File.Move(paths.BackupLaunchScriptPath, paths.VanillaLaunchScriptPath);
}
```

- **VanillaLaunchScriptPath:** `<gameDir>/StardewValley`
- **BackupLaunchScriptPath:** `<gameDir>/StardewValley-original`
- **Why:** Uninstall-first pattern — always restores a clean slate before doing anything else.

### Step 3 — Delete old SMAPI files

Iterates `GetUninstallPaths()` and deletes every file/directory that exists. See Section 5 for the full list.

### Step 4 — Copy SMAPI files from the macOS bundle

```csharp
foreach (FileSystemInfo sourceEntry in paths.BundleDir.EnumerateFileSystemInfos())
{
    if (!this.ShouldCopy(sourceEntry)) continue;
    this.InteractivelyDelete(Path.Combine(paths.GameDir.FullName, sourceEntry.Name), allowUserInput);
    this.RecursiveCopy(sourceEntry, paths.GameDir);
}
```

`ShouldCopy` excludes `"mcs"` (obsolete macOS mono symlink) and `"Mods"` (handled separately). Everything else in the bundle root is recursively copied into `<gameDir>/`.

See Section 2 for the full manifest of what the macOS bundle contains.

### Step 5 — Replace the game launcher

```csharp
// back up & remove current launcher
if (File.Exists(paths.VanillaLaunchScriptPath))
{
    if (!File.Exists(paths.BackupLaunchScriptPath))
        File.Move(paths.VanillaLaunchScriptPath, paths.BackupLaunchScriptPath);
    else
        this.InteractivelyDelete(paths.VanillaLaunchScriptPath, allowUserInput);
}

// add new launcher
File.Move(paths.NewLaunchScriptPath, paths.VanillaLaunchScriptPath);

// mark files executable
foreach (string path in new[] { paths.VanillaLaunchScriptPath, paths.UnixSmapiExecutablePath })
    Process.Start("chmod", $"755 \"{path}\"");
```

- `NewLaunchScriptPath` = `<gameDir>/unix-launcher.sh` (copied from bundle in Step 4)
- `VanillaLaunchScriptPath` = `<gameDir>/StardewValley` (renamed to `StardewValley-original`)
- `UnixSmapiExecutablePath` = `<gameDir>/StardewModdingAPI`
- Both get `chmod 755`.

### Step 6 — Copy `StardewModdingAPI.deps.json`

```csharp
File.Copy(
    sourceFileName: Path.Combine(paths.GamePath, "Stardew Valley.deps.json"),
    destFileName: Path.Combine(paths.GamePath, "StardewModdingAPI.deps.json"),
    overwrite: true
);
```

- **Why:** SMAPI needs to resolve native DLLs (e.g. `libSkiaSharp`) that .NET loads via the game's own deps manifest. SMAPI's separate `.deps.json` is generated by copying the game's file.

### Step 7 — Create `Mods/` directory

```csharp
if (!paths.ModsDir.Exists)
    paths.ModsDir.Create();
```

- **Path:** `<gameDir>/Mods/`
- No-op if already exists.

### Step 8 — Install bundled mods

Copies `ConsoleCommands/` and `SaveBackup/` from the bundle's `Mods/` subfolder into `<gameDir>/Mods/`. If an existing copy is found anywhere under `<gameDir>/Mods/` (by manifest `UniqueID`), that copy is deleted and replaced. Only mods whose `UniqueID` is in `BundledModIds` are allowed; others are warned and skipped.

### Step 9 — Save color scheme preference

If the user picked a theme during the interactive prompt, it is written to `<gameDir>/smapi-internal/config.user.json` via `SaveUserSettings()`. (Not applicable in `--no-prompt` mode with `--install`.)

## Section 3: Files Renamed / Preserved

| Original path | New path | Condition |
|---------------|----------|-----------|
| `<gameDir>/StardewValley` | `<gameDir>/StardewValley-original` | Only on first install; if backup already exists, existing `StardewValley` is deleted without backup |
| `<gameDir>/unix-launcher.sh` (added in Step 4) | `<gameDir>/StardewValley` | Always on install — the launcher is moved, not copied |

No other game files are renamed. All vanilla game files outside these two paths are untouched.

## Section 4: Mods Directory

**Canonical path:** `<gameDir>/Mods/` i.e. `<bundle>/Contents/MacOS/Mods/`

This is the only mods directory the installer creates and writes to. The installer does not create or reference `~/Library/Application Support/StardewValley/Mods/`.

At runtime, SMAPI itself may look at an AppData path for legacy migration (the installer migrates `AppData/StardewValley/Saves/.smapi` → `AppData/StardewValley/.smapi` for SMAPI internal data, not mods). Mod loading at runtime uses only `<gameDir>/Mods/`. **TODO: verify** whether the SMAPI runtime ever loads mods from AppData — the installer does not write there.

## Section 5: Uninstall Procedure

The uninstall path in `InteractiveInstaller.Run()` runs Steps 2 and 3 from the install flow, then stops (no file copies, no launcher replacement).

**Step U1 — Restore original launcher:**
- Delete `<gameDir>/StardewValley` (the SMAPI launcher script).
- Rename `<gameDir>/StardewValley-original` → `<gameDir>/StardewValley`.

**Step U2 — Delete all SMAPI files** (`GetUninstallPaths()` list):

Current SMAPI files:
- `<gameDir>/StardewModdingAPI` (Unix executable)
- `<gameDir>/StardewModdingAPI.deps.json`
- `<gameDir>/StardewModdingAPI.dll`
- `<gameDir>/StardewModdingAPI.exe` (Windows; not present on macOS)
- `<gameDir>/StardewModdingAPI.exe.config`
- `<gameDir>/StardewModdingAPI.runtimeconfig.json`
- `<gameDir>/StardewModdingAPI.xml`
- `<gameDir>/smapi-internal/` (entire directory)
- `<gameDir>/steam_appid.txt`

Obsolete files also deleted if present (legacy cleanup):
- `<gameDir>/libgdiplus.dylib` (pre-3.13)
- `<gameDir>/Mods/.cache` (1.3–1.4)
- `<gameDir>/Mods/ErrorHandler/` (pre-4.0)
- `<gameDir>/Mods/TrainerMod/` (pre-2.0, renamed to ConsoleCommands)
- Many old root-level DLLs moved in 2.8 (`0Harmony.dll`, `Mono.Cecil.dll`, `Newtonsoft.Json.dll`, etc.)
- `~/Library/Application Support/StardewValley/ErrorLogs/`

**Mods are NOT deleted.** `<gameDir>/Mods/` is left intact. The bundled mods (`ConsoleCommands/`, `SaveBackup/`) remain after uninstall — the official installer does not remove them.

## Section 6: Edge Cases / Gotchas

### Gatekeeper / quarantine

The `.command` script runs `xattr -r -d com.apple.quarantine internal` on the *installer* directory only. The game bundle's own quarantine xattr (set when downloaded from Steam/GOG) is **not** cleared by SMAPI. After SMAPI modifies `Contents/MacOS/StardewValley`, macOS may show a Gatekeeper dialog on next launch because the signature is now invalid. The SMAPI install guide tells users to manually open the game once after installing to dismiss the dialog.

**Corkscrew implication:** Corkscrew must clear the quarantine xattr on the files it writes into the bundle:
```bash
xattr -d com.apple.quarantine <path>
```
Or use `std::process::Command` to call `xattr` for each written file/directory.

### Code signing

Modifying any file inside `Contents/MacOS/` invalidates Apple's code signature on the `.app` bundle. SMAPI does **not** re-sign. The bundle becomes ad-hoc or unsigned, which Gatekeeper accepts after the user's first-run approval dialog. Steam and GOG re-verify the bundle on their own update paths, which will overwrite SMAPI files on game updates — this is expected and documented behaviour.

### Mono runtime

SMAPI does **not** bundle or require Mono. Since SMAPI 3.x on macOS, the game and SMAPI both run under .NET (not Mono). The `mcs` file referenced in `ShouldCopy()`:

```csharp
"mcs" => false, // ignore macOS symlink
```

...is an old Mono C# compiler symlink from pre-3.x installs. SMAPI actively excludes it. No Mono installation is required.

### GOG vs Steam

The installer detects the game by scanning known paths (including `/Applications/Stardew Valley.app/Contents/MacOS` for GOG and `~/Library/Application Support/Steam/steamapps/common/Stardew Valley/Contents/MacOS` for Steam). The mutation procedure is identical for both. `steam_appid.txt` is always installed regardless of platform.

### Idempotency

Running the installer twice is safe. The installer always uninstalls first (Steps 2–3), then reinstalls. The backup-launcher logic is guarded: `if (!File.Exists(paths.BackupLaunchScriptPath))` — so a second install will not double-backup. If the backup already exists, the current `StardewValley` (which is the SMAPI launcher from the first install) is simply deleted.

### Non-interactive mode

The installer supports `--no-prompt --install --game-path <path>`. In this mode:
- No terminal is opened.
- No color-scheme is prompted; scheme stays `AutoDetect`.
- `config.user.json` is not written for color scheme.
- All other file operations are identical.

This is the mode Corkscrew should use.

## Section 7: Implementation Notes for Corkscrew

### Which steps are simple file ops

All of the following can be implemented as pure Rust `std::fs` operations:

| Operation | Rust API |
|-----------|----------|
| Copy `StardewValley` → `StardewValley-original` | `fs::rename()` |
| Copy bundle files into `<gameDir>/` | `fs::copy()` + `fs::create_dir_all()` |
| Move `unix-launcher.sh` → `StardewValley` | `fs::rename()` |
| Copy `Stardew Valley.deps.json` → `StardewModdingAPI.deps.json` | `fs::copy()` |
| Create `Mods/` | `fs::create_dir_all()` |
| Copy bundled mods | `fs::copy()` recursively |
| Delete SMAPI files on uninstall | `fs::remove_file()` / `fs::remove_dir_all()` |

### Which steps require a shell call

| Operation | Shell call |
|-----------|-----------|
| `chmod 755` on `StardewValley` (launcher) | `std::process::Command::new("chmod").args(["755", path])` |
| `chmod 755` on `StardewModdingAPI` (binary) | Same |
| Clear quarantine xattr on written files | `std::process::Command::new("xattr").args(["-d", "com.apple.quarantine", path])` |

Alternatively, `chmod` can be done in pure Rust using `std::os::unix::fs::PermissionsExt`:
```rust
use std::os::unix::fs::PermissionsExt;
let mut perms = fs::metadata(&path)?.permissions();
perms.set_mode(0o755);
fs::set_permissions(&path, perms)?;
```

### Recommended approach: replicate file ops in Rust

Do NOT run the official installer script. Reasons:
- The `.command` script requires the full installer zip to be unpacked — a ~42 MB download with the C# installer binary, which Corkscrew would then immediately discard.
- The installer is interactive-by-default; `--no-prompt` mode requires careful argument threading.
- All file operations are simple and fully specified above — no dynamic detection logic is needed beyond finding the game directory (which Corkscrew already does).

**Recommended install sequence for Corkscrew (Task 3.4):**

1. Download and extract SMAPI release zip (`SMAPI-X.Y.Z-installer.zip`).
2. Locate the macOS bundle directory inside: `SMAPI X.Y.Z installer/internal/macOS/install.dat` (a zip within a zip). Extract `install.dat`.
3. Perform the file ops in order: backup `StardewValley` → `StardewValley-original`, copy bundle contents (excluding `mcs` and `Mods`), move `unix-launcher.sh` → `StardewValley`, `chmod 755` both executables, copy `deps.json`, create `Mods/`, copy bundled mods.
4. Clear `com.apple.quarantine` on all newly written files.

**Recommended uninstall sequence for Corkscrew (Task 3.5):**

1. Delete `StardewValley` launcher.
2. Rename `StardewValley-original` → `StardewValley`.
3. Delete all files listed in Section 5, Step U2.
4. Leave `Mods/` intact (do not delete user mods).

### Non-interactive invocation (if running the official installer is ever preferred)

```bash
internal/macOS/SMAPI.Installer --no-prompt --install --game-path "<path>/Contents/MacOS"
```

This produces no prompts. Still requires the full 42 MB installer download. Not recommended.
